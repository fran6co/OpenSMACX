When this brief drives a headless provider command, the final answer must be the bare JSON object the bridge schema names: no markdown code fences, no prose before or after it.

Read `AGENTS.md` and `recovery/WORKFLOW.md`. Remain read-only: no source, task,
policy or Git edits, compilation, preparation, provider calls or subagent launch.
The framework owns authorization, isolation, dispatch and verified publication.

Read-only framework diagnostics still need `uv` cache locks. If the sandbox
refuses such a command, request approved execution of that same read-only command
using `sandbox_permissions: "require_escalated"`; automatic review decides.
Use `uv run --no-sync --frozen` to avoid environment/project synchronization.
Do not bypass a denial, loosen the sandbox, install dependencies, compile, or
edit source/decisions. Report denied or unavailable inspection as evidence.

Select meaningful progress toward genuine recovered C++, not an easy no-op or
an increase in byte-claim count. Inspect eligible ownership groups, their source
and interfaces, coupled callers/lifecycle, original evidence and outstanding
structural debt. Prefer a coherent bounded group whose evidence supports actual
implementation or structural correction within the delegated scope. A class can
need recovery even when individual bodies match. Existing seeds and annotations
are evidence, not proof of the right hierarchy, globals, lifetime or member types.

Use `uv run recover partition --group <selector> --details --impact` and source
inspection for candidate groups; `uv run recover tasks context <task>` explains
existing work. `uv run recover inspect <address-or-symbol> --image "$OPENSMACX_IMAGE"
--callers` supplies mapped original evidence without compilation. Cache reports
only in ignored build storage if needed. Never pipe the whole-project gate or
run it from this read-only role.

Respect request eligibility and external reservations, including reserved task
IDs, subjects and files. Do not inspect or repair another checkout to make it
selectable. Do not create a replacement task for existing reserved work, invent
original bounds, narrow a group's identities, or target recognized dependencies.
Include additional regular product source files only with concrete ownership or
caller evidence and within the delegated limit. Shared declarations may require
additional coupled identities; do not pretend editing permission proves that
verification scope is sufficient. Discovery coordination can investigate current
scope, but the current project delegation grants no later expansion.

Creation fixes the current committed source baseline; resumption preserves the
existing baseline and all restoration obligations. Prefer new eligible work when
existing tasks require unavailable authority, preserved source or unsupported
historical context; explain the actual evidence, not a speculative easy score.
If no eligible task can make meaningful progress within authority, defer with
the concrete missing evidence or capability. A deferral is not acceptance.

Return the exact supplied snapshot and configured response schema. Evidence
must identify inspected source/original relationships and why this ownership
scope is appropriate. Do not claim the proposed task is already recovered or
that a successful build establishes a working game.
For `resume` or `defer`, return empty `group` and `intent` strings and an empty
`editable_files` array. For `defer`, `task_id` must also be empty. Put the
deferral reason in `evidence`, not `intent`.
