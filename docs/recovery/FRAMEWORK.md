# Structure-led recovery implementation

This is the implementation contract and progress record for the independent
`match-recovery` package in `packages/match-recovery/`. The existing recovery tools remain
active until replacement coverage and a measured cutover are demonstrated.
Their continued presence during construction is not a compatibility promise.

New projects now start with native source/measurement/driver configuration via
`recover init`, not a local operation dispatcher stub. An explicitly supplied
original can be pinned in source without copying its bytes; compiler and build
interaction remain configured executable boundaries. Native inventory, task
context and historical obligations run directly from that starter. The unused
project-wide dispatch fallback is removed. This improves onboarding, not backend
coverage: native measurements remain PE/COFF i386, and compiler recipes, source
evidence, full acceptance and autonomous recovery are not inferred by setup.

The native `recover survey` now exposes executable-first starting points without
requiring a legacy function catalogue. Bounded PE/i386 static traversal retains
entry/direct-call provenance, source and component correlations, decode conflicts,
indirect-flow gaps and unfinished budgets. It generates no source and invents no
function/TU boundaries; these observations are inputs for establishing recoverable
identities, not completed executable-to-source seeding or application coverage.

`recover bind` now bridges independently interpreted original extents to existing
C++ candidates using guarded source publication. Binding rationale stays beside
the marker and reaches native task context, while current status remains measured.
The compiler-backed ownership control now uses initialization, image survey and
this binding path before its structural-regression/restoration loop. Original
bounds in that control come from its known reference, not candidate size or survey
reachability. Its worker/reviewer remain deterministic controls, not a live-agent
pilot or full OpenSMACX acceptance.

The configured loop now uses the package-owned `tasks check-restoration` command:
current strict binary/layout measurements are joined to source-history obligation
identities, including removed claims. These are disposable measurements, not a
new ledger. Matching permissions also require a separate passing reference check;
legacy byte-only history cannot waive wrong or unknown targets. The native
`check-build` command now supplies fresh configured artifact measurements to each
driver round, without project checker code or existing incremental outputs.
The provider-neutral `agent` bridge now connects configured prompt-driven commands
to worker/reviewer JSON contracts; local provider arguments remain project data.
Native baseline/current COFF preservation now compares non-scoped compiler output
and outside source bindings, with explicit controls and immutable task history.
Historical header/seed file sets now use the package's complete-tree compiler
protocol, preserving absent/new files without mutating the current checkout.
Preservation reports now expose exact symbol/reference differences and source
navigation hints. Selected-TU diagnostic mode avoids the full damage-control sweep
but always remains unverified; it is investigation, not migration admission.
Full structure, historical product-TU recipe mapping, full-link outside-scope admission
and an OpenSMACX live recovery pilot remain unfinished. A bounded, test-owned live
worker/reviewer/native-acceptance control is now verified as described below.

Compiler execution now has one project-owned implementation shared by native
checks and the retained production measurements. The masked comparer requires an
explicit compiler callable; VC6 command extraction and retry codes no longer live
in the library. CMake uses the environment entry points directly and the four old
build-path shims are removed. Generic compilation-database parsing remains in the
package, preserving argv tokens and duplicate recipe identities. Nonzero compiler
exits can no longer contribute leftover objects to the old gate.

The package now owns `recover check`, with native source integrity, mapping/body
links, history identities, all configured audits, a fresh build, historical match,
symbol, initial-data and layout stages. Additional project checks are explicit
bounded commands, not a project operation dispatcher. `recover check-matches`
remeasures all current claims and built candidates through the configured compiler
with per-TU reuse and no persistent verdict memo. This project's seed-only donor
recipe is explicit compiler policy, not an inferred original TU environment.
Native `recover prepare` now generates fresh compiler recipes through configured
commands, sharing the fresh-build runner and preserving generated include context
in ignored storage. It publishes the validated database without deleting existing
build caches. The native gate prepares before its measurement snapshot; standalone
checks use coordinator-prepared recipes. The old configure CLI and legacy gate
are removed. Native full-gate damage controls and restored-baseline comparison
cover the replaced route.
Those project controls now live in opt-in `recovery/tests/test_gate_controls.py`:
full native gates in a disposable detached checkout, named stage/subject assertions,
and guarded damage restoration. The old main-tree mutation CLI is removed.
Ordinary anchor/safety tests are not a substitute for executing the live matrix.
CMake's debugger support now uses native `recover debug-sidecar`; the former
sidecar and CodeView scripts are removed. PCH imports use recorded signatures and
index ranges, with shared bounds-checked COFF/value parsing. Debugger hints stay
separate from strict recovery verification. Frame guarantees and source-path
translation are supplied by the project build, not chosen by the package.
All standalone diagnostics now use native `recover inventory`, `recover inspect`
and `recover measure`; the legacy status/show/calls/measure commands are removed.
Measurement groups requested current spellings by TU; private candidate decks use
`recover tasks variants`, with task scope and compiler damage controls. Neither
route banks claims or treats a matching unfinished placeholder as recovery.
The local live-reference script is removed. Native `recover check-references`
checks configured source/documentation roots, including the recovery instructions;
the gate tracks reference-target existence as well as instruction bytes.
Native compiler-observed layouts now cover conventional header offsets; the old
guessed-size walk is removed. Controlled source-derived witnesses expose otherwise
unemitted declarations, without hiding conflicting product definitions.
Native acceptance now coordinates the gate,
restoration/preservation and configured structure/runtime proof commands. Complete
OpenSMACX proof coverage remains unfinished; an incomplete native gate does not
permit deleting the old control route.

The full gate's duplicate-global and scaled-pointer checks now use the native
configured storage audit; their standalone tools are removed. Original-address
conflicts retain cross-file source locations and participate in ownership-task
context. Compact object identities and conventional legacy bindings are analyzed
together, distinguishing first-member address notes from separate global storage.
Existing limits remain project policy. Missing coverage, malformed identities and
inconsistent reports are refused. This is a lexical diagnostic, not proof of
aliasing, hierarchy or lifetime. Conventional initial-data and header-offset
coverage is now native; full production cutover and structural proof remain unfinished.

Native initial-data verification now compares source-bounded object storage to
compiled definitions using standalone CodeView extents and strict relocation
targets. The package-owned `check-data` command also serves data-only projects;
it requires no legacy function seeds. Task checks/decks reuse the verifier, and
source-history interpretations retain initialization requirements across rehoming
and removal. Original bounds and evidence anchors live in v2 object annotations;
observed results are disposable. Native `check-initializers` now covers the
conventional trailing-address probes separately; those hints are not bounded
object proofs. Complete object layout and CRT/runtime lifetime
remain unfinished.
The native production gate consumes that verifier too: matching functions
cannot excuse incorrect initialized data, and unbounded source objects keep the
gate incomplete. Native checks run after the fresh build jobs, not concurrently
on their shared compiler environment. Standalone forward type records resolve
only to one complete same-kind qualified-name definition in the same COFF stream.

Recording and the native gate share the package's per-TU measurement engine,
including span refusals, absent-symbol trials and similarity-first ranking. The
recorder groups requested functions before dispatch instead of compiling each
separately; the gate's duplicate comparison loop is removed. Reuse is invocation
local, including failed compiles. Changed selected hosts refuse publication and
global shared-span changes participate in fresh input identity. A 12-function Caviar-family
control compares grouped and individual measurements without changing source;
the measured timings belong in the cutover commit, not a current-status ledger.
This is not a fleet-throughput claim.

The recording mutation path now uses package-owned guarded publication. Input
snapshots cover configured source/build/compiler-policy inputs and environment,
the selected image and legacy command inputs. Complete measurement coverage is
required before staging. Only byte obligations are added; historical notes and
existing obligations survive nonmatching measurements. The old demotion and
weaker-claim grant/withdraw paths, along with automatic count reconciliation,
are removed. Source-only publication no longer maintains a count floor.
Original/replacement bytes are staged in ignored storage. Ordinary write failures
roll back the invocation's own unchanged outputs, preserving conflicting later
edits and recoverable backups. Multi-file atomicity and compact obligation writing
remain open.

Production recording now runs through installed `recover record`, with native
source selection and configured compiler JSON interaction. The old recording CLI,
its project orchestration and recorder-specific mutation tests are removed; synthetic
compiler-protocol controls exercise their replacement. Exact host disambiguation,
full input/HEAD/image validation, explicit argument files and source-only guarded
publication are package owned. Default serial TU dispatch avoids inventing compiler
capacity; optional jobs share no in-process object cache across TUs. This still
records historical masked-byte obligations, not strict reference or structural
acceptance. Compact annotations, full gate and migration admission remain open.

Native `recover check-claims` now replaces the count floor in production recording
and the full gate. It derives byte/shape requirements from the existing structural
baseline through reachable source history, including merged branches, and requires
their original identities to remain represented in source. Same-count swaps,
weakened requirements and deleted markers fail; renames, rehoming and removal of
redundant seed copies preserve identity. The one-time `source_history.baseline_revision`
decision cannot be advanced or reset after it appears in reachable configuration
history. No counts, inventories or fresh match results are persisted. Current
measurements, ownership, references and structural acceptance remain separate.

The production gate's annotation-integrity dependency now runs through native
`recover check-source`; the replaced script is removed. The package checks actual
source text, marker coverage and in-memory claim/lesson transitions across configured
source roots. Its stronger lesson-deletion control rejects unrelated equal-line-count
edits. Missing inputs and empty coverage remain unverified. Complete application
acceptance remains separate from the production gate.

The address/build-host check now uses native `recover check-mappings`, with only
a compilation-database path and forwarder macro names supplied by the project.
No hardcoded scaffold exemption list remains. Full paths expose four pairs of
complementary seed candidates the old basename check hid; these remain visible
hints while ambiguous production mappings fail. Historical claims still undergo
the independent measurement sweep. The replaced index, unused automatic-homing
implementation and its scratch batch caller are removed; the active ownership
partition/task/discovery workflow replaces their nearest-address and copy/revert
policy. Compiler/link ownership, full acceptance and migration remain unfinished.

## Accepted design

- Identify application, third-party, runtime, system, generated, and unknown
  components before dispatching recovery. Reuse pinned upstream code and system
  bindings; verify dependencies without counting them as application recovery.
- Begin with an ownership/partition pass. Distinguish historical compilation
  units (only when supported by evidence), current source homes, and structural
  task scope. A unit owns a collection of original code/data spans, not a single
  contiguous executable range. Propose units from source/class/component evidence;
  leave uncertain assignments open instead of inventing a file per function.
- Use classes, object ownership and dependent functions as work units; use
  functions/spans as measurement units. Real C++ structure takes priority over
  locally convenient source forms. VC6 remains the OpenSMACX compiler target.
- Source owns the load-bearing mappings, symbols, obligations, structural
  decisions and provenance needed to understand its relationship to the image.
  Ordinary C++ expresses relationships wherever possible; annotations must not
  duplicate what declarations and definitions already express. Names and source
  paths are not ids.
- Recompute anything derivable from the authoritative inputs. Current match
  verdicts, censuses, call/dependency graphs, parsed mappings, context cards and
  stale/fresh status are outputs, not durable records. Persist them only as
  disposable, input-keyed caches; deleting every cache must preserve correctness
  and obligations. Historical observations never become current verdicts.
- Keep all lasting recovery information in Git-readable source or text records.
  No SQLite authority: the uncommitted prototype was replaced by hash-chained JSON
  events with atomic publication and ignored kernel-lock files. A fresh checkout
  can read the history without a database or private artifact cache.
  Versionability alone is not a reason to persist an output: tracked JSON is for
  non-derivable workflow decisions and checkpoints, not derived reports.
- Import old source, Kuna/Ghidra/IDA output, notes and prior experiments as seeds
  with provenance, including conflicting interpretations. Do not copy scaffolds
  into production source as a mandatory rehoming step.
- Admit scoped structural migrations through independent review and deterministic
  checks even with tracked matching regressions. Keep every old obligation;
  checkpoint on budget exhaustion, close only after restoration. A verified
  revision advances only on a full passing gate.
- Verify relocation targets, boundaries, layouts, lifetimes and bindings rather
  than accepting masked-byte agreement as structural or runtime correctness.
- Package core/target/provider/agent contracts independently. Declarative tasks
  own context, scope, discoveries, budgets, acceptance and durable resumption.
- Consolidate measurement, compile once per affected TU/configuration, lease
  isolated Wine prefixes, and use content/dependency-aware caches and candidate
  decks. Measure throughput, do not assert it.
- Preserve original and proprietary derivatives only in ignored artifact storage.
  Preserve upstream license/provenance and keep vendor sources unmodified.

## Persistence boundary

Store inputs and decisions; compute conclusions. Essential image/source bindings,
accepted layout interpretations and restoration obligations belong beside their
owning source declarations or definitions. A required match is an obligation,
not a stored assertion that the current source matches. The gate computes the
current result, including during an accepted structural migration.

Tracked workflow records may preserve agent/human hypotheses, externally supplied
hints, approved scope, review decisions and choices needed to resume work. Promote
accepted load-bearing discoveries into the source instead of leaving JSON as a
second authority. Use Git messages for completed-change rationale, not as the only
home of an outstanding obligation. Do not copy source bodies, parsed inventories
or reproducible measurement summaries into durable history.

Cache keys must cover every relevant source, image, toolchain, configuration and
analysis-version input. A cache miss triggers recomputation; unavailable required
inputs produce an explicit unmeasurable result, never a cached claim of success.
External hints and execution decisions are not reproducible merely because an
agent could be asked again. Preserve those inputs, not duplicate conclusions that
can be regenerated from them.

## Isolation and integration

The user authorized integration and continuing framework work on `master` after
the interrupted rehoming merge was resolved. Inspect concurrent changes at clean
checkpoints; preserve other agents' work. Recovery workers still need isolated
worktrees, build outputs, caches and compiler prefixes. The pinned image and
immutable toolchain inputs may be shared read-only. The coordinator owns branch
updates and integration; never stash, discard work or run automatic fast-forward
setup against an established task baseline. Rebuild context and rerun checks
after integrating changes. Do not collect/reap another agent's work unasked.
